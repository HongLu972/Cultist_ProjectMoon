# Cultist Simulator (Project Moon Mod) – Data & System API Documentation v1.1

This game is built on a **purely data-driven** architecture. By modifying JSON files, you can completely rewrite the story, adjust numerical values, add new cards, or even create large-scale story mods—all without touching a single line of Java code.

## 📂 File Directory Structure
*   `assets/data/`: Core game data (cards, events, text).
*   `assets/audio/`: Audio files (`.wav` or `.ogg` are strongly recommended).
*   `mods/`: External mod folder (located at the same level as the game executable, used to override or add content).
*   `saves/`: Auto-generated game save folder.

## ⚙️ 1. Global Configuration (`config.json`)
Defines the basic parameters of the game.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `language` | String | Yes | Default language code, e.g., `"zh"`. |
| `speeds` | Array | Yes | Speed multipliers shown in the top-right corner, e.g., `[0.75, 1, 1.5, 2]`. |
| `worldWidth` | Float | Yes | Width of the world map (in pixels). |
| `worldHeight`| Float | Yes | Height of the world map (in pixels). |

## 🃏 2. Card Definitions (`elements.json`)
Defines all cards that players can drag, consume, or obtain. **A card's ID is implicitly treated as one of its aspects.**

```json
[
  {
    "id": "health",
    "image": "img/cards/health.png",
    "aspects": { "body": 1 },
    "lifetime": -1,
    "decayTo": "disease_flu",
    "stackable": true,
    "triggers": [
      { "slot": "work", "event": "work_basic" },
      { "slot": "use", "event": "use_health" }
    ]
  }
]
```
| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Globally unique ID. |
| `image` | String | (Optional) Relative path to the card image. |
| `aspects` | Object | (Optional) Key-value pairs of aspects. |
| `lifetime` | Float | (Optional) Lifetime in seconds. Omit or set to `-1` for permanent. |
| `decayTo` | String | (Optional) ID of the card this decays into upon expiry. Omit to disappear. |
| `stackable` | Boolean | (Optional) Whether the card can be stacked. |
| `triggers` | Array | (Optional) Trigger rules. `slot` can be a verb ID or `"use"` (double-click). `event` is the event ID. |

## 🎬 4. Event System (`events.json`)
The heart of the game. Contains event bodies, timelines, forced draining, and action trees.

### 4.1 Event Body Structure
```json
[
  {
    "id": "time",
    "start": "manual",
    "slot": "none",
    "autoStart": true,
    "time": 30.0,
    "forceDrainAspects": ["hope", "despair"],
    "slots": [ { "id": "time_slot", "required": true } ],
    "action": [ ...action tree... ],
    "products": [ { "card": "eye", "amount": 1 } ]
  }
]
```
| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Globally unique event ID. |
| `start` | String | Start mode: <br>`manual`: Player triggers by placing cards.<br>`auto`: Silent background loop.<br>`linked`: Only triggered by other events. |
| `slot` | String | ID of the occupied verb slot. Use `"none"` for an independent event window. `auto` and `linked` events must be `"none"`. |
| `autoStart`| Boolean | (Optional) Only for `manual`. Starts automatically when conditions are met, no button click needed. |
| `time` | Float | Duration in seconds. |
| `forceDrainAspects` | Array | (Optional) **Priority-based forced draining**. During the event, any unlocked cards on the table with these aspects will be forcibly pulled into empty slots (e.g., `["hope", "despair"]` prioritizes Hope, then Despair). |
| `input` | Object | (Optional) Aspect threshold required to start, e.g., `{"body": 1}`. |
| `slots` | Array | (Optional) List of extra slots generated by the event. `id`: unique ID; `accepts`: accepted aspects; `required`: whether mandatory. |
| `action` | Array | (Optional) Action tree executed upon resolution. |
| `products` | Array | (Optional) List of products. Delivered via the `{"type": "produce"}` node. |

### 4.2 Action Tree Nodes (Action)
Action trees consist of multiple nodes. Each node returns "success" or "failure" after execution, triggering the corresponding child nodes. All nodes support `"onSuccess": [...]` and `"onFail": [...]`.

#### Basic Effects
*   `{"type": "create", "target": "eye", "amount": 1}`: Creates cards on the table. Always succeeds.
*   `{"type": "consume", "target": "money", "amount": 1}`: Consumes cards with the target aspect from the **current window's slots**. Fails if not enough.
*   `{"type": "drain", "target": "health", "amount": 1}`: Drains cards with the target aspect from the **entire table** (unlocked). Fails if not enough.
*   `{"type": "produce"}`: Delivers all products in the event's `products` list.

#### Control Flow
*   `{"type": "check", "aspects": {"mind": 1}}`: Checks if the total aspect count in the current window/table meets the condition.
*   `{"type": "chance", "percent": 50}`: Coin flip, succeeds with the given percentage chance.
*   `{"type": "trigger", "event": "next_event"}`: Triggers another event.
*   `{"type": "end_game", "ending": "poverty"}`: Immediately ends the game with the specified ending.

#### System Commands
*   `{"type": "unlock_verb", "verb": "study"}`: Unlocks a new permanent action window.
*   `{"type": "play_music", "track": "audio/bgm_boss.ogg"}`: Seamlessly switches background music.

## 🌐 7. Localization (`text_zh.json` / `text_en.json`)
> [!WARNING]  
> **Extremely Important**: All text displayed in the UI **must not** be hardcoded in Java. The system dynamically generates Chinese fonts by scanning characters appearing in JSON files. Hardcoding text will result in square blocks or errors.

Fixed key naming conventions:
- **Cards**: `element.<ID>.name` / `.desc`
- **Aspects**: `aspect.<ID>.name`
- **Verbs/Slots**: `slot.<ID>.name` / `.desc`
- **Events**: `event.<ID>.name` / `.desc` / `.result` (written to the log upon resolution)
- **Endings**: `ending.<ID>.name` / `.desc`
- **System UI**: `ui.start`, `ui.paused`, `ui.log`, etc.

## 🛠️ 8. Engine Advanced Features (Player's Guide)

### 💾 8.1 Multi-Save System
*   **Shortcuts**: Press `Esc` in-game to open the menu for saving/loading. (Press `Space` to purely pause/resume time).
*   **Menu Operations**: Includes 20 independent save slots with **custom naming** (e.g., "First Despair," "Arbiter Defeated").
*   **Save Location**: Stored in the game root directory under `saves/slot_1.json` through `slot_20.json`. Perfectly restores card coordinates, event timers, slot data, and the chronicle.

### 🧩 8.2 Mod Loading
> [!NOTE]
> The mod system is an advanced feature. Monitor the console logs during loading to prevent data conflicts.

1.  Create a `mods` folder in the game root directory.
2.  Create a subfolder with any name (e.g., `mods/NewStory/`).
3.  Place JSON files with the same names inside (e.g., `elements.json`, `events.json`).
4.  The engine merges them sequentially at startup. **Duplicate IDs will override the base game data**.

### 🎵 8.3 Music System
*   Place audio files in the `assets/audio/` directory.
*   **Strongly recommended** to use `.wav` or `.ogg` format. LibGDX's native decoder has extremely poor compatibility with `.mp3`, easily causing crashes or system error sounds.
*   Use the `play_music` event action to switch BGM during dramatic story moments.
